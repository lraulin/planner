  later one.** `nearestOccurrence` (`src/lib/finances/billSchedule.ts:170`) documents "ties go

- `8019ce2` — **A parent cycle crashed every grid with a Status column.**
  `scheduleStatusById` (`src/lib/tree/status.ts:263`) is the one downward walk in the tree
  code with no cycle insurance: `walkUp` covers every upward walk and `derive`'s rollup is an
  iterative reverse pass that skips a child it has not reached, both written for a cycle a
  corrupt import can create and `moveNode` refuses to. So `derive` hands the nodes over
  happily and `visit` recursed — it memoizes into `result` only _after_ the child loop, so
  re-entering an open node found nothing cached and A→B→A ran until the stack gave out. A
  `RangeError` out of a server component takes down Outline, Projects, Tasks, Goals and the
  Chooser. Open nodes are now tracked during the walk. — verified by `status.test.ts`
  "survives a parent cycle rather than exhausting the stack" and "still rolls a cycle's urgent
  child up to the node that reached it"; both raise `Maximum call stack size exceeded` with
  the guard removed.

- `e454bf0` — **The Projects grid's Tasks column hung on a project cycle.** Found by

  "counts a task reached twice only once" (the fast signal for the same guard) after.

## Needs a decision

- **CI does not run `npm run build`, and nothing else does either.** `.husky/pre-commit` runs
  lint / typecheck / unit; `.husky/pre-push` runs the full suite; `.github/workflows/ci.yml`
  runs lint, typecheck and `npm test`. None builds. `AGENTS.md` says the build "catches things
  the other three don't", and the workflow's own header says it exists for "branches that
  never touch Lee's machine" — which is exactly the Dependabot case where a bump that breaks
  the build would go green in CI and fail at the Vercel deploy.
  **My recommendation:** add `- run: npm run build` after `npm test`. Two things I checked
  that make it look safe: `scripts/migrate-on-deploy.mjs` exits 0 immediately unless
  `VERCEL_ENV === "production"`, so it is a no-op in CI; and the only module-scope env a build
  needs is `DATABASE_URL` (`src/db/index.ts:19` calls `connectionString()` at import), which
  the job already sets.
  **Why I did not just do it:** I cannot run a GitHub Actions job from here, and proving the
  build works without a `.env.local` would have meant moving Lee's `.env.local` aside on a
  machine I am unattended on. Verifying that is a two-minute job for whoever is awake; making
  CI red overnight is not worth the guess.
  — blocking: nothing today, but it is the difference between Dependabot being gated and
  looking gated.
