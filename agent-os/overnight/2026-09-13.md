## Shipped

- `4227d3a4` — **An IME composition's confirming Enter also fired the app's commit/submit.**
  Flagged last night as noticed-but-not-spread ("the only evidence it matters to you is one
  dev-database note with CJK text"). Typing in a CJK input method previews the syllable being
  composed; Enter confirms it into the field. None of the app's 37 `key === "Enter"` handlers
  checked for that, so the same Enter also ran the handler's commit/submit/select — on the
  value as it stood mid-composition, which drops or duplicates the last character depending on
  browser and timing. Added `isComposingKey` to `src/lib/keyboard.ts` (checks the standard
  `isComposing` flag and the legacy `keyCode === 229` some browsers send instead) and applied
  it at 17 genuine free-text commit sites: the two shared grid cell editors (row names used by
  nearly every grid; free-text cells used by Goals/Wishes), note titles and bodies, budget/bill
  category and chart names (three near-duplicate `RenameInput` copies — billColumns.tsx says
  outright it was "copied rather than imported" from Budget's), the contact discussion composer,
  quick capture, and Find's search box.
  Left alone on purpose: numeric and date fields (not composable), single-letter priority/rank
  inputs (`A1`, not realistic IME targets), menu/row Enter-or-Space activation (not text), and
  the combobox pickers (ContactSelect, ExercisePicker, TitlePicker, CategorySelect, the command
  palette) — same shape but wrapped in arrow-key list navigation that deserves its own look
  rather than a blind copy of this patch. Also skipped `src/components/day/**`
  ([[day-view-may-be-removed]] — Day view is on its way out).
  Verified `isComposingKey` with unit tests (including the plausible mistake of checking only
  `isComposing` and missing the 229 fallback), and the real browser mechanics on a throwaway
  `example.com` tab — no app, no database — with an actual `new KeyboardEvent("keydown", {
isComposing: true })` dispatch: suppressed as expected; an ordinary Enter still fires;
  `keyCode: 229` also suppressed.

## Needs a decision

- **The combobox pickers have the same IME bug but weren't touched tonight.**
  `ContactSelect.tsx`, `ExercisePicker.tsx`, `TitlePicker.tsx`, `CategorySelect.tsx`, and
  `CommandPaletteDialog.tsx` all do `if (event.key === "Enter") { ...choose(rows[active])... }`
  while a filtered list is open from live-typed text. Composing-Enter there would prematurely
  pick whatever's highlighted from a not-yet-final query, not corrupt saved text — lower
  severity than the commit-on-Enter bug, but the fix needs to interact correctly with the
  arrow-key navigation each one already owns, so I didn't copy tonight's one-liner blind. Not
  really a design question — recommend the same `isComposingKey` guard on each Enter branch —
  just wanted a dedicated look rather than a rushed 18th file in the same commit. Low urgency:
  only bites while actively typing CJK/Japanese-style text into a picker's search box.
