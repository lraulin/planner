- `db54dc7` — **Select the rows the grid is showing, not the ones handed to it.** Six views
  — Notes, Day, Wish List, Contacts, Resources, Time Charts — built `useMultiSelect`'s
  order from the rows they passed *into* `DataGrid`, but the grid owns the narrowing
  (`DataGrid.tsx:426-490`: filters, quick search, advanced filter, multi-column sort,
  collapsed groups). The other six were fixed by `onNavigableIdsChange` in the right-click
  slice; these were missed. Reproduced and then re-broken to be sure: search `/notes` for
  `2014-07-31`, click `2014`, Shift+Down twice — the toolbar reads **`3 selected`** and
  offers **`Delete (3)`** while exactly one row is highlighted, because the other two are
  the next rows in the *unfiltered* tree. On Notes that Delete removes two notes the user
  cannot see; on Day the same list drives Rank A–D, the Mark states and Move to tomorrow
  (`DailyItemsGrid.tsx:217`). Fixed by `useNavigableIds`, which also keeps the fallback
  array memoised. Verified in the app both ways —
  `.artifacts/planner-shots/notes-shift-range.png` shows the three highlighted rows now
  matching the three the count claims.

- `ff6da72` — **Walk the Metrics rows in the order they are drawn.** `navigableIds` came
  from `visible` (pre-grouping) while both the table and the compact list render `grouped`,
  which hoists the ownerless group to the front and then goes alphabetically by owner —
  and `sortKey` interleaves owners. Reproduced with one metric owned by a goal: the table
  drew Dante Weight / New Metric / Bodyweight, and on Bodyweight (the bottom row) ArrowUp
  left it where it was while ArrowDown jumped to Dante Weight at the top. Confirmed both
  ways by reverting the source and re-running the same steps.

- `177471f` — **Remember how the Metrics tab is set up.** All five switches — Active only,
  Group by Owner, Show Performance, Show Legend, Show Objective — were component
  `useState`, so `/metrics` reset them on every visit: turn off Active only to find a
  retired metric, go to the Outline and back, and it is hidden again. Metrics is the module
  with no `GridToolbar`, which is how it missed the rule the persistent-UI-state slice set
  for every other tab. Stored in the `grid:metrics-layout` scope the pane height already
  uses, since `parseMetricsLayout` falls back per key and a blob holding only a height
  keeps it. Four new codec cases, including false-is-not-absent and the pre-upgrade blob.
  Verified in the app — `.artifacts/planner-shots/metrics-persisted.png`, Active only off
  and Group by Owner on after a hard reload.
