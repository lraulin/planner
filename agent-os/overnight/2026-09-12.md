## Needs a decision

- **Per-user timezone is still the biggest open date question** (08-07, 08-25, 08-30). Nothing
  new tonight except a count: 40-odd server-side `localDateKey(...)` calls read the server's
  zone, including `applyStateTransition`'s completion day (`tree/mutations.ts:930`) — whose
  comment says it exists to beat "evening in the Americas" and only does so where the process
  runs in the user's zone. The test suite pins `TZ=America/New_York`, so nothing in the gate
  can see it. Recommendation unchanged: store an IANA zone on the account.

- **A Proposed item reads "Ongoing" in the Status column.** `scheduleStatus` computes
  `started = effective !== "not_started"` (`tree/status.ts:108`), so every state other than
  Not Started counts as started work — including `proposed`, which `date-model.md` defines as
  "uncommitted incubation — idea / Someday". A Someday project with no dates therefore shows
  Ongoing, Achieve's word for "started, no near end date"; give it a target end last week and
  it reads Behind Schedule for being unfinished. Achieve's manual only says "has been started",
  and its Current filter treats _In Progress and Should Delegate_ as the ongoing states.
  Options: (a) count `proposed` as not started — it then reads Not Scheduled with no dates,
  which fits Someday, but Need to Start / Behind Schedule once it has a past target start;
  (b) give proposed its own early return, like `waiting`, so no plan band applies until you
  commit to it; (c) leave it. **Recommendation: (b)** — an uncommitted idea is not behind on
  anything — but it changes what a status filter matches, so it's yours. `delegated` has the
  milder version of the same question. — blocking: nothing, one-line change once decided.

## Noticed but didn't touch

- **A day-31 monthly appointment means two different things depending on whether Google is
  linked.** Local series now clamp (Feb 28, Mar 31, Apr 30). A series created with a push
  target goes to Google as `FREQ=MONTHLY` (`google/mapping.ts:215`) and comes back as Google's
  own expansion, which follows RFC 5545 and **skips** months with no 31st — so no February,
  April, June, September or November occurrence at all. The monthly preview can't tell you
  which you'll get. Options: send `BYMONTHDAY=-1` when the start is the last day of its month
  (matches the clamp for the 31st only, not the 29th/30th), or accept the split. It only bites
  on days 29–31, so I'd leave it unless you create such a series.
