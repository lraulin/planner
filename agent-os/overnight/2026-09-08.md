  A repair that lists what it would change and asks once is the only version that is both
  honest about the source and honest about the model. Not taken tonight because it changes
  your data.

## What the dry night says

Last night's five bugs all came from one detector: **find a claim the codebase makes about
itself, then check the code against it.** I ran that detector again tonight across the
docstrings, the standards and the frozen specs, and it found three stale sentences and no
defects — which is what you would expect once the obvious claims have been checked once.

The technique that earned its place tonight is different and complementary: **check the
invariants against the data instead of against the code.** A dozen SQL queries over your
real database tested the same promises the unit tests test, on rows nobody wrote a fixture
for, in about the time it takes to run the suite once. It found the one thing worth your
attention (8 contradictory parents), one harmless artefact of a fixed bug, and confirmed
eleven invariants the code is only assumed to maintain. It is also the only sweep here that
would notice a defect that has already stopped happening but left damage behind — which is
exactly the category a green test suite is blind to.
