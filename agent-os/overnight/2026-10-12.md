## Noticed but didn't touch

- **The Amazon userscript's money patterns are ASCII-hyphen only**
  (`amazon-subscribe-save.user.js:183, 193, 450`): `-?\$…`. Same shape as the Chase bug, but
  there is no evidence Amazon typesets its savings with U+2212 (nothing in the repo's
  fixtures does), and the server side already reads U+2212/U+2013 through
  `parseAmountCents`. Left because widening a pattern I cannot check against Amazon's real
  HTML would cost Lee a reinstall for a problem nobody has seen. If a Subscribe & Save saving
  ever imports as a positive number, this is where to look; the harness in
  `chaseUserscript.test.ts` is the template.
- **`fetchPageTitle` (attachment "Fetch name from page") will fetch any http(s) URL,
  including private addresses, following redirects, and returns the page's `<title>`**
  (`src/lib/url/pageTitle.ts:104`). Behind a session and title-only, and on Vercel there is
  nothing internal to read, so I left it — but on a self-hosted box it is a way to read the
  title of an internal admin page, and this app does have invite-created second users. The
  guard from `f3091028` is the starting point if it is ever worth closing.
- **Invites never expire and are multi-use until revoked** (`auth/invites.ts`); and OAuth
  authorization codes are stateless HMACs, so one cannot be made single-use within its
  5-minute life (PKCE still binds it to the verifier). Both are visible design trade-offs
  rather than defects; noting them because a leaked invite link is a standing way to mint
  empty accounts until someone revokes it.
- **CSP blocks FullCalendar's icon font.** Every page that mounts FullCalendar logs
  `Loading the font 'data:application/x-font-ttf…' violates … "font-src 'self'"`
  (Calendar, Week Plan, Time Charts, Day). FullCalendar embeds its `fcicons` glyph font as a
  `data:` URI. Nothing visible depends on it — both calendars set `headerToolbar={false}`
  and no `dayMaxEvents`, so the only `.fc-icon` (the "+N more" popover's close button) is
  unreachable. Widening `font-src` to `data:` would be a security trade `csp.ts` argues
  against, so it is left as console noise. If a `+more` popover is ever enabled, its close
  button will render blank until `font-src` allows `data:` or the icon is replaced.
- **`format:check` fails on six markdown files** (`roadmap.md` and five frozen spec
  `plan.md`s / an old overnight report). Each diff is one `*emphasis*` → `_emphasis_` or a
  list indent; lint-staged only formats what is staged, so they were never run through
  Prettier. Not reformatted: frozen specs stay untouched, and `format:check` is in neither
  CI nor a hook.
- **`payee:audit` reports 27 city/state-glued payee spellings** on the dev ledger
  (`GRAY MIRRORHTTPSGRAYMIRRCA` → `GRAY MIRROR`, 52 charges; `DOMINO'S 6066CALIFORNIAMD` →
  `DOMINO'S`; 8 `UNITED AIR …PAYPAL COMTX`) and three damaged names (`SP`, `BP`, `P`). It is
  read-only and designed to be confirmed one merge at a time; flagging only that the
  normalizer still fragments these.
- **A card page row in a Capital One "posted" region that shows `Purchased:` but no
  `Posted:`** would be filed as pending (`capitalone-pending.user.js:254`,
  `row.id.startsWith("Pending-") || !postedDate`). `expand()` waits for `Posted:` so I
  could not construct how it happens, and a missing `Posted:` with no `Purchased:` already
  fails the row. Unverifiable offline; noting the branch.
